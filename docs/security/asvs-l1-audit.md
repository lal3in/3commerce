# OWASP ASVS L1 Self-Audit — 3commerce

Pre-launch security self-audit of the custom auth (Identity) and the gateway, against
OWASP ASVS Level 1. Scope: ADR-0012 conditions, PRD §9. Status legend: ✅ pass · ⚠️ partial/follow-up · ⬜ deferred (post-registration) · n/a.

> This is a **self-audit**, not a substitute for the external review that is a launch gate
> (PRD Appendix B). It records the current posture so findings are tracked, not lost.

> **Refresh 2026-07-11** (post multi-tenant expansion): MFA shipped (follow-up 4 ✅); tenant
> isolation now includes PostgreSQL RLS defense-in-depth (V4 row added); webhook verification is
> per-provider with a rotation-safe secret registry (13.x updated); payment modes are fail-closed
> with boot guards (14.3.x row added); product visibility is status- and price-gated on public
> surfaces. Verdict unchanged: no critical open findings pre-launch.

> **Refresh 2026-11-27** (rows below re-checked against the code at `6c290572`): the gateway now refuses
> `/api/{service}/internal…` from the public origin (#322); refunds need the `payment.refund` permission through
> the service PEP (`PermissionGate`, #326); payment vaults and saved cards are under FORCE RLS (#331/#339); auth
> rate limiting is distributed over Valkey and keyed per tenant + storefront + IP (ADR-0044); email bodies and
> links are never logged outside Development and the collector redacts tokens/emails as a backstop (#303);
> security logs are kept 12 months (ADR-0065). Update (same day): the storefront now has an
> `npm audit` gate too (14.2.1 is ✅ again).
>
> **Finding 2026-11-27 (4.2.1, fixed the same day):** an IDOR in Support — any order id unlocked its refundable lines
> (anonymously), an RMA and its tickets for any signed-in customer. See the 4.2.1 row.
