| [0052](./0052-coupon-codes-and-redemption-limits.md) | Coupon codes at checkout — a coupon IS a code-gated `Promotion` (ADR-0051), not a second entity: optional `Promotion.Code` (trimmed UPPERCASE, filtered-unique per tenant among non-null codes, matched case-insensitively) plus `MaxRedemptions` / `MaxRedemptionsPerCustomer` (null = unlimited; single-use is simply 1), projected via `PromotionChanged` into `PromotionCopy`; a code-gated promotion may carry NO threshold (the code is the gate). Ordering owns `PromotionRedemption` (Reserved/Confirmed/Released, unique on `(PromotionId, OrderId)`) and an Ordering-only `RedeemedCount` the projection never resets. The redemption is **reserved at checkout, before the payment is authorized** — because the charged amount is fixed there — and released by the saga's single cancellation path (failed payment / cancel / 30-min expiry), confirmed on `CheckoutCompleted`; both status-guarded and idempotent. The cap is race-safe via ONE conditional `UPDATE ... SET RedeemedCount = RedeemedCount + 1 WHERE MaxRedemptions IS NULL OR RedeemedCount < MaxRedemptions` (rows-affected is the answer), the per-customer limit via a transaction-scoped advisory lock on (promotion, customer); `CustomerKey` = `u:{userId}` else `e:{lowercased email}`, so guests count. Distinct localized refusal reasons (unknown / inactive / not started / expired / wrong storefront-or-currency / threshold / usage limit / per-customer limit) on `GET /cart/summary` (validates, never reserves) and as a 400 at checkout. Stacking stays the existing `Combinable` flag; no new ledger line — trial balance stays 0. Extends ADR-0051/0047/0041/0007 | Accepted | Catalog / Ordering / pricing |
