# scripts/

| Script | What it does |
|---|---|
| `dev-up.sh [--fresh] [--with-frontends] [--seed] [--dummy-data\|--data empty\|catalog\|smoke\|dummy\|full\|exhaustive\|mirror-prod]` | **Bare-run** local env (ADR-0009): only the **infra set** (`lib/infra.sh`) in Docker, infra → migrate → all services → (frontends) as host processes. The infra step is **all-or-nothing**: it brings every member up with `--wait`, heals a partial infra (missing/stopped members start, unhealthy ones restart, running ones are left alone), checks every healthcheck + readiness probe, and exits **1** naming any container that is not running and healthy — idempotent on a fully-up infra. `--with-frontends` starts Storefront `:3000`, Admin `:5200`, and SupplierPortal `:5300`. The light default — never builds images, so it can't OOM the Docker VM. `--fresh` first wipes the Postgres data volume (`dev-down --clean`) for a guaranteed-clean start — empty DB → latest migrations → fresh seed on latest-built code; use it whenever local state has drifted (a demo run mutated data, a stale/corrupt DB survived a plain restart). Ends with a **readiness gate**: prints `Up.` only once gateway, RabbitMQ, pgAdmin, Kafka UI (cluster online), Grafana, Loki, Tempo, Mimir (and the frontends) are genuinely ready; otherwise names what is not and exits **3**. `--with-frontends` also clears the storefront's `.next/` before starting it. Data profiles: `empty` = as-is/no seed, `catalog` = current sample importer (`--seed`), `smoke` = fast deterministic fixture manifest, `dummy`/`full` = broad demo data via `dev-dummy-data.sh`, `exhaustive` = slower scenario hook, `mirror-prod` = reserved placeholder for a future sanitized prod mirror. |
| `dev-down.sh [--clean\|-v]` | Stops everything `dev-up.sh` started, then removes **every** infra container (all profiles, overlay orphans, the borrowed observability services, stopped/exited ones, hand-made squatters on an infra container name) and **verifies none remain** — exit **1** naming any survivor. Idempotent. `--clean`/`-v` also removes the Postgres data volume — plain `down` keeps it, which is why a mutated/corrupt DB can survive restarts; use `--clean` (or `dev-up.sh --fresh`) for a clean slate. `--clean` also removes **orphaned containerised-stack volumes** (e.g. `3commerce_rabbitmq_data` left by `launch.sh`, which bare-run never mounts); a plain down only names them. See `lib/volumes.sh`. |
| `run-all.sh [start\|stop]` | Starts/stops the gateway + services + workers (host `dotnet run`, detached via nohup). **Verbose by default** (app Debug + EF SQL + MassTransit) → logs carry their own diagnosis; quieten with `LOG_LEVEL=Information`. Used by `dev-up.sh`. |
| `dev-dummy-data.sh [--profile smoke\|core\|full\|exhaustive\|mirror-prod]` | Seeds a running dev stack through gateway APIs and writes `.run/dev-dummy-data/fixtures.json` for deterministic Playwright fixtures. `smoke`/`core` import catalog + demo shopper, `full` also attempts tenant/operator data across Entity, Marketing, Pricing, Payments, Fulfillment, Entitlement, and Usage, `exhaustive` is the state-rich scenario hook, and `mirror-prod` is intentionally a no-op placeholder until a sanitized production snapshot flow exists. |
| `build-images.sh` | Builds **all** container images with **bounded concurrency** (`PARALLEL=2`) + a Docker-memory preflight, so 13 parallel .NET builds can't OOM the VM. |
| `docker-compose.infra.pgbouncer.yml` / `docker-compose.pgbouncer.yml` | Optional compose overlays (not scripts) that expose PgBouncer on `:6432`; the app overlay routes runtime service database connections through PgBouncer while migrations stay direct-to-Postgres. Use with `--profile pgbouncer`. |
| `docker-compose.infra.kafka.yml` / `docker-compose.yml --profile kafka` | Optional Apache Kafka KRaft dev stack for the durable stream lane (ADR-0034), plus Kafka UI on `:8088`. RabbitMQ remains the operational bus and Kafka is not required for normal dev checkout flows. |
| `doctor.sh` | One-shot local-env diagnosis: the infra set as `up` / `down` / `PARTIAL (missing: …)` (per container; **PARTIAL exits 1**) + per-service `/health/ready` (manifest-driven) + recent errors from anything down. Run it first when something misbehaves. |
| `host-check.sh [--deep] [--logs] [target…]` | Full-stack sweep of a host: containers, service health, **RabbitMQ bus state** (stuck/competing queues), Postgres/RabbitMQ logs, observability, compose, host resources + the Colima OOM log; on `local` also the dev infra `up`/`down`/`PARTIAL` state (PARTIAL exits 1). Runs over **local / SSH VPS / GCP** (Hostinger/EC2/GCE/Azure VMs via `ssh`); `--logs` pulls CloudWatch/GCP/Azure managed logs when configured. |
| `postgres-index-audit.sh [--list\|probe]` | Captures read-only `EXPLAIN (ANALYZE, BUFFERS)` plans for known hot PostgreSQL query paths. Use against a seeded stack before proposing partial/expression/composite indexes (ADR-0033). |
| `ci-logs.sh [branch]` | The latest CI run's failing jobs + their error lines (automates the `gh run view --log \| grep` triage). |
| `pr-merge-on-green.sh <pr>` | Squash-merges a feature/defect PR **into `develop`** once its gates (`changes`, `build-test`, `integration`, `browser-e2e`; override with `REQUIRED=`) are green — never `--admin`; refuses any PR whose base isn't `develop` (ADR-0058). A failed required gate is rerun (≤`MAX_RERUNS`, default 3) only after its whole workflow run completes, counting only reruns GitHub accepted. Talks to GitHub only — never `git checkout`, so it can't switch your working tree's branch; deletes the remote head branch via the API. Lists any non-gating checks still red at merge time (they block promotion to `test`). Run it in the background. |
| `promote.sh test` · `promote.sh main --user-approved` | Release promotion (ADR-0058): fast-forwards `test` to `develop`'s tip, or `main` (production) to `test`'s tip. Refuses unless the move is a fast-forward and all six gates (`changes`, `build-test`, `integration`, `browser-e2e`, `compose-smoke`, `kind-deploy`) are green on that exact commit; `main` also requires `--user-approved` — agents ask the user before every production release. Pushes the existing commit (`<sha>:refs/heads/<stage>`), never touches your checkout. `DRY_RUN=1` shows what would move. |
| `clean-agent-worktrees.sh` | Removes finished subagent worktrees (`.claude/worktrees/agent-*`) and leftover local branches. A worktree goes only when it is clean (ignored build output aside) **and** its branch's PR merged at exactly that commit, or its commit is already in `develop` and it has been idle > `STALE_HOURS` (24); a running agent is always kept. Then deletes unused `worktree-agent-*` branches already in `develop` and any branch whose tip is a merged PR's head; never `main`/`develop`/`test`/the current branch. Runs automatically after each merge (`pr-merge-on-green.sh`) and at session start (`.claude/settings.json` hook). `DRY_RUN=1` only prints; `QUIET=1` prints removals only. |
| `e2e-verify.sh [--live\|--live-only]` | Full regression: build, format, unit, integration, storefront, (live smoke). The storefront production build goes to `.next-verify/`, never the dev server's `.next/`. Live mode leaves the machine **exactly as found**: it **reuses** a fully running stack (no build/migrate/restart/teardown), boots-and-stops its own on a clean machine (teardown by port — never a `pkill` pattern), and refuses a partial one. Same for the infra: fully up → used and left up; down → the full set is brought up (as `dev-up` does) and taken fully down again at the end (also on Ctrl-C); PARTIAL → refused. On CI (`CI=true`) the set is the core one (Postgres + RabbitMQ + Valkey), override with `INFRA_SET=core\|full`. |
| `screenshots/shots.cjs <index\|compare\|history\|promote\|import>` | Screenshot history (no dependencies). Every Playwright run archives its shots under `test-artifacts/screenshots/runs/<runId>/` (gitignored, never pruned) with `INDEX.md`; `compare [--from] [--to] [--diff]` classifies by decoded pixels (`same`/`minor`/`changed`) and can write red-highlight diffs; `promote <runId> [--all]` is the only way the wiki images change (refuses shots from failing tests; copies only images that look different from the wiki's current ones unless `--all`). See docs/help/testing.md. |
| `lib/hosts.sh` | Host targets for `host-check.sh` (name\|transport\|detail). Add your VPS / cloud VMs here. |
| `lib/services.sh` | **Single source of truth** for the service list (name:path:port). Edit here when adding a service. |
| `lib/infra.sh` | **Single definition of the local infra set** — all-or-nothing. `full` (default) = every `docker-compose.infra.yml` service under the `portals` profile + `DEV_BORROWED_SERVICES` (the observability services bare-run borrows from `docker-compose.yml`); `core` = the profile-less infra services (CI). Members, container names and healthchecks are read from the compose files. `infra_up` (heal + `--wait` + probes, fails naming stragglers), `infra_down [-v]` (every member, then verify none remain), `infra_state` (`up`/`down`/`PARTIAL (missing: …)`), `infra_report`. Used by dev-up, dev-down, e2e-verify, doctor, host-check. Add a readiness probe in `_infra_probe` for a new member without a healthcheck. |
| `lib/volumes.sh` | Which Docker volumes belong to which mode. `DEV_BORROWED_SERVICES` (from `lib/infra.sh`) is the single list dev-up/dev-down use, and their volumes form the keep-set; `prune_app_stack_orphans` / `report_app_stack_orphans` act on the rest of compose project `3commerce` that no container mounts. Fails safe (prunes nothing) if the keep-set can't be read; never touches `3commerce-db`. |
| `lib/preflight.sh` | `require_docker` / `require_docker_memory` guards used by the bring-up scripts. |

## GUI helper

`tools/script-console/script_console.py` is a stdlib Python/Tkinter GUI that discovers every `scripts/*.sh` file, orders scripts by normal workflow purpose, explains each script in plain language next to its Run button, streams output, and shows Docker/container/image, service-health, package-version, and host-stat status. Each row has **View/Edit .sh** so the operator can visually inspect or update the exact shell file before running it. Run it from the repo root with:

```bash
python3 tools/script-console/script_console.py
```

**Memory note:** the Docker VM (Colima) needs ~8+ GiB to build the images. Bare-run (`dev-up.sh`) only needs
Docker for the infra set (no image builds — it pulls stock images), so it works on a small VM. To build images, bump it first:
`colima stop && colima start --cpu 4 --memory 12`.

**Maintaining these:** `scripts/lib/services.sh` is the single service source (most scripts derive from it). For when to update each script/doc as the codebase changes, see the **maintenance-triggers table** in `AGENTS.md` (Rules).
